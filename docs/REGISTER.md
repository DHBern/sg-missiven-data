# Register: authority links and generated entries (issue #12)

Two additions to the edition's registers (`person/person.xml`, `place/place.xml`).
Neither is part of the edition, and the viewer marks both as such.

## 1. Authority links for the edition's own entries

`scripts/authority_links.py` adds links (HLS, Wikidata, GND, Human Lineage) to
register entries **only from identifiers the entry already has**, through
Metagrid, Human Lineage and Wikidata. A name alone never makes a link.

- **Output:** `registers/authority_links.json`, with 191 links and 14 conflicts (13.11.2026).
- **Name matches:** these go to `registers/authority_candidates.tsv`, for review only.

## 2. Generated entries for names only in letters not yet edited

`scripts/auto_register.py` makes a register entry for every name that the
automatic tagging (docs/NER.md) found in the letters not yet edited and that the
edition's registers do not have. Fragments, bare forenames and names the edition
already has are dropped.

Each entry is marked **automatisch generiert** and carries up to three candidates
from HLS, Human Lineage and Wikidata. Metagrid adds its concordance for the
persons graded sicher or wahrscheinlich.

The candidates are graded by rule:

| | sicher | wahrscheinlich | möglich |
|---|---|---|---|
| Persons | forename and surname, spelling ≥ 95, dates fit, no rival | spelling ≥ 90, dates fit, clearly the best | spelling ≥ 82, dates fit |
| Places | never | the spelling is a name of an item with an HLS article | an exact name without HLS article, or a close spelling (≥ 85) |
| Organisations | never | never | an item of exactly that name |

For persons, "dates fit" means the letters' years (the draft regest's year, or the
neighbouring letters') lie within the candidate's adult life.

### Measured precision (14.11.2026)

The rules were measured on the edition's own entries with a known HLS or Wikidata
id, spelled as the letters spell them (`registers/auto_register_measure.json`):

| | sicher | wahrscheinlich | möglich |
|---|---|---|---|
| Persons (190) | 32 / 34 = **94 %** | 5 / 8 = 62 % | 5 / 8 = 62 % |
| Places (337) | – | 61 / 82 = **74 %** | 19 / 77 = 25 % |

The first place rules ("sicher" = the only exact match, or by far the nearest to
St. Gallen) were right only 34 % of the time. Old spellings (Limperg, Mastrick,
Belletz, Wesen) name other, modern places. So a place is never "sicher".

### The run of 14.11.2026

There are 13,354 entries:

- **Persons (10,126):** 72 sicher, 25 wahrscheinlich, 50 möglich, 9,979 without a candidate. Most of the persons named in these letters are not in HLS or Wikidata.
- **Places (2,264):** 127 wahrscheinlich, 463 möglich, 1,674 without a candidate.
- **Organisations (964):** 48 möglich.

Wikidata's search API refused this address with 429 after the person lookups.
So the places and organisations were looked up through the Query Service
(`auto_register.py prefetch`). That route finds a name only where it is exactly
an item's label or alias in de/fr/it/en/la. The measurement above used the same route.

### Commands

    auto_register.py groups      # the names, counted
    auto_register.py prefetch    # places/orgs via SPARQL, into the cache
    auto_register.py measure     # -> registers/auto_register_measure.json
    auto_register.py link        # -> registers/auto_register.json

Answers are cached in `registers/.cache/`, which is not committed. A rerun asks
only for what is new.

### On the site

`scripts/build_site.py` adds the entries to `registers.json`, flagged `auto`.
Tags in the letters not yet edited that carry an entry's spelling point to it,
flagged `auto_reg`.

The Names and Places pages can filter by origin (the edition, generated, or
generated by grade). An entry's page shows the candidates with their grade and
its measured precision. Generated entries never go into the TEI.
